授权验证原理篇——域名绑定、签名加密与防篡改机制
域名绑定的基本逻辑
域名授权验证的核心是“授权码与域名绑定”。客户端运行时会获取当前访问域名，将其与授权码中的域名信息比对，并向服务端发送验证请求。服务端校验请求来源、授权码、域名、时间戳、随机数、签名等参数。若域名不匹配、授权过期、被列入黑名单，则返回失败。绑定粒度可支持主域名、子域名、泛域名、多域名、IP、MAC 地址等。为兼顾开发与测试，系统通常支持本地域名白名单、测试模式、离线宽限期。

授权码的结构与生成
授权码通常由载荷和签名组成。载荷包含授权 ID、客户 ID、绑定域名、到期时间、功能权限、版本限制、最大设备数等。载荷经 Base64 编码后，使用服务端私钥进行非对称签名（如 RSA、ECC），生成最终授权码。客户端使用公钥验证签名，确保授权码未被篡改。也可使用 HMAC 对称签名，但非对称更安全，因为客户端不持有私钥。授权码可设计为短码、长码或授权文件。

加密与签名算法
常用算法包括：RSA/ECC 非对称加密用于签名与密钥交换；AES 对称加密用于敏感数据传输；HMAC-SHA256 用于请求签名；SHA-256 用于哈希校验；Base64 用于编码。请求参数通常包括：授权码、域名、时间戳、随机数 nonce、客户端版本、签名。服务端校验时间戳有效期，防止重放；校验 nonce 唯一性，防止重复请求；校验签名，防止篡改。HTTPS 是基础，防止中间人攻击。

在线验证与离线授权
在线验证实时性高，但依赖网络。离线授权通过本地授权文件实现，文件包含授权信息与签名，客户端使用公钥验证。离线授权适合内网、隔离环境或服务端故障时使用。系统可设计“在线优先、离线宽限”策略：正常时在线心跳，异常时允许离线运行若干天。离线授权需注意文件复制风险，可结合域名、IP、机器码绑定。

防篡改与防重放
防篡改依靠签名与哈希。客户端代码可校验自身文件完整性，防止被修改。通信使用 HTTPS 与请求签名，防止参数被改。防重放依靠时间戳、nonce、序列号。服务端可记录已用 nonce，拒绝重复。频率限制防止暴力破解。黑名单机制可封禁泄露的授权码。日志审计记录所有验证请求，便于追踪异常。

密钥管理与开源注意事项
开源版需特别注意密钥管理：私钥绝不能放在客户端；公钥可分发；数据库密码、API 密钥使用环境变量；日志脱敏；后台启用强密码与双因素。开源代码可能被审计，因此算法与实现应经得起检验，避免自创加密算法。建议使用成熟库，如 OpenSSL、Sodium。授权协议应明确禁止破解与传播。

结语：域名授权验证的本质是“信任但验证”。通过域名绑定、非对称签名、时间戳、随机数、HTTPS 与黑名单，PHP 域名授权验证系统开源版可在开放网络环境中构建较高的防篡改与防伪造能力。
